# W9.4b-iii — Image thumbnail pipeline + asset URL unfurl in comments

**Status**: 🟡 Spec — 2026-05-30 (not yet executed). One spec, two pieces, because they're co-dependent: the unfurl chip needs the medium thumbnail to load fast.

**Slice of**: W9 Collaborative Inbox · W9.4b (the generic Collab layer).

---

## 1. The visible feature

> Paste a Kanzen URL into a comment / task / list note → it auto-replaces with a rich preview chip showing the **thumbnail + name + subtitle**. The same thumbnails make the search results, ⌘K, MediaGallery, and Inventory cards feel snappy everywhere they appear.

Two halves that ship together as W9.4b-iii:
- (A) **Image thumbnail pipeline** — every uploaded image gets `small` / `medium` / `large` variants at upload time, served via the existing blob token with a `?size=` param.
- (B) **Asset URL unfurl** — `GET /api/unfurl?url=…` + a `<LinkPreview>` chip; the CollabPanel comment renderer auto-substitutes recognised URLs.

Use cases for the same thumbnail set:
- Comment unfurl chip (medium).
- Search results + ⌘K (small).
- MediaGallery grid (medium); lightbox (large + "Open original").
- Inventory grid hero (medium).
- AssetDetail hero (large); maintains snappy first paint.

---

## 2. Current state (audited 2026-05-30)

- Uploads land via `MediaGallery` → `POST /api/documents` → `ObjectStore.put(originalKey, bytes)` (`com.kanzen.s3.ObjectStore`) → `documents` row carries `storage_key`, `content_type`, `size_bytes`.
- Blobs served via `/api/blobs/<signed-token>` (single size = the original). Token signs the document id + expiry.
- `documents` table has **no thumbnail columns**.
- `MediaGallery.tsx`, `AssetDetail.tsx`, `Inventory.tsx`, `Documents.tsx` all use the same presigned URL for every size context — the original.
- No image-processing library in `backend/build.sbt`.

## 3. Thumbnail pipeline

### 3.1 Sizes (max edge, longest side preserved)
| Tier   | Max edge | Where it's used |
|---|---|---|
| `small`  | **96 px**   | Search results, ⌘K, mention chips, list densities. |
| `medium` | **320 px**  | Unfurl chips, MediaGallery grid, Inventory grid hero, comment preview. |
| `large`  | **1080 px** | AssetDetail hero, lightbox initial paint. |
| original |  ∞         | "Open original" in lightbox; kept immutable (the source-of-truth document — F05 invariant). |

All thumbnails encode to **JPEG at q=82** (browser-safe, EXIF stripped, ~80% quality is the sharpness/size sweet spot). Original stays in its source format.

### 3.2 Library

**Thumbnailator** (`net.coobird:thumbnailator:0.4.20`).
- Single Java dep, no Scala wrapper needed, deterministic output, ~250 KB jar.
- Avoids Scrimage's transitive deps and AWT bootstrap weight.
- Works on the JVMs we already run (CI + dev + EC2 NixOS).
- Edge case: animated GIFs — Thumbnailator takes the first frame. Acceptable; we don't expect Kanzen to be a GIF surface.
- SVG: skip (Thumbnailator can't render vectors). SVG stays original-only; `thumbs` map will be `{}` and the frontend falls back to original.

### 3.3 Schema — V3_8_0

```sql
-- W9.4b-iii: per-document thumbnail set, generated at upload for image content types.
-- jsonb beats three nullable columns: survives future tier changes (e.g. adding 'webp_medium') without further migrations.
alter table documents add column if not exists thumbs jsonb not null default '{}'::jsonb;

-- Example: {"small":"docs/u1/d1/thumb-small.jpg","medium":"...","large":"..."}
```

No index needed (we read `thumbs` only via document id lookup).

### 3.4 Upload hook

In `Documents.scala`, after the existing `store.put(originalKey, bytes)`:

```scala
for {
  _      <- store.put(originalKey, bytes, contentType)
  thumbs <- if (contentType.startsWith("image/")) generateThumbs(documentId, ownerId, bytes, contentType) else Map.empty.pure
  _      <- DocsRepo.insert(... , thumbs = thumbs.asJson)
} yield ...
```

`generateThumbs` (new module `com.kanzen.media.Thumbnails`):
1. Loads the input bytes once.
2. For each of the three tiers, calls `Thumbnails.of(in).size(maxEdge, maxEdge).keepAspectRatio(true).outputQuality(0.82).outputFormat("jpg")`.
3. Uploads each to `documents/<owner>/<docId>/thumb-<tier>.jpg`.
4. Returns `Map[String, String]` of tier → key.

Failure tolerance: wraps in `IO.attempt`; on failure logs and returns `Map.empty` → the original still saves with `thumbs = {}` and the frontend falls back. Avoids "upload fails because thumbnail failed."

### 3.5 Backfill

One-shot job `ThumbnailBackfill.run(xa, store)`:
- Iterates documents where `content_type LIKE 'image/%' AND thumbs = '{}'::jsonb`.
- For each: fetches original bytes via `store.get(key)`, runs `generateThumbs`, persists.
- Resumable (stateless — re-running just skips already-thumbnailed rows).

Run once on dev `down -v` reseed. In prod, run during the W9.5 cutover.

### 3.6 Blob serving — `?size=`

Extend the existing `/api/blobs/<token>`:
- New optional query: `?size=small|medium|large|original` (default `original` — preserves today's behaviour).
- Handler resolves token → document; if size param is set and `thumbs.size` exists, signs and serves that key; otherwise falls back to original.
- Token verification unchanged. Sizes don't leak across documents — the token is still scoped to the document id.

```scala
// (sketch)
def serve(token: String, size: Option[String]): IO[Out[Stream]] =
  for {
    docId <- verifyToken(token)
    doc   <- DocsRepo.get(docId)
    key    = size.flatMap(s => doc.thumbs.findKey(s)).getOrElse(doc.storage_key)
    bytes <- store.get(key)
  } yield Right(bytes)
```

### 3.7 Frontend integration

`services/documents.ts` exposes `urlFor(token: string, size?: Size)`:
```ts
export type Size = "small" | "medium" | "large" | "original";
export const urlFor = (token: string, size?: Size) =>
  `${API_URL}/api/blobs/${token}${size ? `?size=${size}` : ""}`;
```

Surface migration:
- **MediaGallery**: grid thumbs → `medium`; lightbox initial paint → `large` + "Open original" link → `original`.
- **Inventory**: hero on each card → `medium`.
- **AssetDetail**: hero → `large`; lightbox unchanged.
- **Documents**: grid → `medium`; preview iframe unchanged for non-images.
- **Search** (§5): result row thumb → `small`.

## 4. Asset URL unfurl

### 4.1 Backend — `GET /api/unfurl?url=…`

```scala
final case class UnfurlPreview(
  entityType: String,     // asset | task | property | person | calendar | thread | list | vendor | document
  entityId: UUID,
  title: String,
  subtitle: Option[String],   // category / payee+amount / property name / role / etc.
  thumbnailUrl: Option[String], // medium-size blob URL (via the token path)
  href: String                  // canonical Kanzen URL (normalised)
)
```

Recognised URL patterns (relative or absolute against any Kanzen origin):
- `/inventory/<uuid>` → asset
- `/tasks/<uuid>` → task
- `/properties/<uuid>` → property
- `/people/<uuid>` → person
- `/calendar?event=<uuid>` → calendar event
- `/inbox?thread=<uuid>` → email thread
- `/lists/<uuid>` → list
- `/vendors/<uuid>` → vendor
- `/documents/<uuid>` → document

Parsing: a small `UrlPatterns` table with regex + (type, id) extractor. Adding new types = one entry.

Resolution: per `entityType` → a label resolver function (already partly built — `CollabInboxRepo.assetTitle`, `.listName`, `.personName`; extend). Returns `(title, subtitle, heroDocumentId?)`.

If `heroDocumentId?` is set, mint a blob token at `size=medium` and put the URL into `thumbnailUrl`. Tokens here are short-lived (5 min) — the chip embeds them once and the frontend caches.

### 4.2 Authz — no leak

The unfurl **runs the same view-check as the entity's detail endpoint**:
- `asset` → `asset:view`
- `task` → `task:view`
- `property` → `property:view`
- `person` → `person:view`
- `expense` → `expense:view` (+ Principal-private; Manager gets field-stripped subtitle)
- `email_thread` → `inbox:view` + mailbox visibility tier (W9.4 RBAC)
- etc.

If the actor can't view it: **403**. The frontend renders the URL as a plain text link (no leak via the unfurl rejection — same shape whether the entity exists and is hidden, or doesn't exist at all).

For Principal-private entities accessed by Manager: 403 unless field grant — easier than returning a partially-stripped preview.

### 4.3 Frontend

`<LinkPreview href={url} />` component:
- Queries `/api/unfurl?url=<encoded>` via TanStack Query (5 min stale).
- Loading: a skeleton chip (text-only placeholder, no flash).
- Success: themed chip — `[thumbnail medium][title • subtitle]`, clickable to navigate.
- Error / 403 / unrecognised pattern: falls back to a plain `<a href>{url}</a>`.

`<CollabPanel>` body renderer change:
- Today: walks for `@Name` mentions only.
- New: also walks for the recognised URL patterns; splits the body into `text | mention | linkPreview` nodes; renders `<LinkPreview>` for each link node.
- Multiple unfurls per comment: fine — each is its own block (one per line).

Composer hint (small polish):
- On paste of a recognised URL, optionally toast "Linked to <title>" so the user knows the chip will render. Skip on first iteration if it complicates things.

### 4.4 Reuse

`<LinkPreview>` is reusable wherever a Kanzen URL appears in user-authored text:
- Tasks: description / notes (when those become rich).
- Lists: item notes.
- Property Bible: rich descriptions.
- Future DMs / chats.

The CollabPanel renderer is the first consumer; others adopt it as those surfaces grow.

## 5. Search integration (the user's explicit ask)

> "the same images can be used in the advanced search functionality and everywhere else"

- The `Search` API response gains an optional `thumbnailUrl: Option[String]` per result.
- For results that have a `heroDocumentId` (assets, properties, people with a photo, documents that ARE images), the API mints a small-size blob token and serves it.
- ⌘K result rows + `/insights` lists render the thumbnail inline (24px square).
- Filterable: a "with photo" facet on `/inventory` becomes trivial (a `heroDocumentId is not null` predicate already exists).

## 8. Dependencies / risk

- One new Java dep — `net.coobird:thumbnailator:0.4.20`. Tiny, no transitive headaches.
- Upload latency: ~150–300ms per image for the three-tier pass (single-threaded JPEG encode). Acceptable for a household upload cadence. Could move to background later if a surge hits.
- Storage cost: 3 extra files per image at ~10-50KB each. Negligible.

## 9. Implementation order

1. **Migration V3_8_0** — `thumbs jsonb on documents`.
2. **`Thumbnails`** module + Documents.scala hook + `ThumbnailsIT`.
3. **Backfill job** — runs at boot in dev (one-time idempotent sweep).
4. **`/api/blobs/<token>?size=`** support + IT.
5. **Frontend services + MediaGallery/Inventory/Documents** consume sized URLs.
6. **`/api/unfurl`** for `asset` + `task` + `property` + `person` first; others follow.
7. **`<LinkPreview>`** + CollabPanel renderer + e2e.
8. **Search results + ⌘K** thumbs.

One commit per step. Steps 1–5 = the thumbnail pipeline shipped. Steps 6–8 = the unfurl ships on top.

## 10. Out of scope (deliberately)

- WebP / AVIF output. JPEG is universally supported and ~good enough. Add a flag later if needed.
- Image cropping UX. Server picks a centred square for `small`; medium/large preserve aspect.
- PDF first-page preview. Cool, separate work, uses pdfbox.
- Animated GIF preservation (first-frame is fine — Kanzen isn't a GIF surface).
- Pre-rendering thumbnails for non-image documents (PDF icons are fine as glyphs).
